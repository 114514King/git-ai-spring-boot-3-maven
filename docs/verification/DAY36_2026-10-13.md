## 检查与结果

常规测试在同一流程中使用明确禁用的生产适配器；单独真实检查在测试配置中启用官方客户端。两者都经过真实本地 HTTP，均执行 13 个请求。真实检查执行于北京时间 10:18:17.122–10:18:33.125（包含测试上下文启动），只有下表三条请求调用模型。

| 成功请求 | 发送消息数 | HTTP 响应历史数 | 官方结果 | 输入 / 输出 token |
| --- | ---: | ---: | --- | --- |
| 学生首轮，本人投递 11 | 3 | 2 | 200 / GENERATED / stop | 293 / 133 |
| 学生同会话续聊 | 5 | 4 | 200 / GENERATED / stop | 455 / 73 |
| HR 所属岗位的投递 11 | 3 | 2 | 200 / GENERATED / stop | 294 / 263 |

使用运行环境中的密钥，未打印或保存密钥；请求及返回模型均为 `deepseek-flash`，测试固定 2048 token / 30 秒超时。3/3 完整、0 截断、0 降级，共 1511 token（1042 输入、469 输出），无重试；这是接口报告用量，不是账单或模型质量指标。

| 被拒绝请求 | HTTP 状态 | 次数 |
| --- | ---: | ---: |
| 匿名 | 401 | 1 |
| 学生调用 HR、HR 调用学生入口 | 403 | 2 |
| 其他学生的投递、简历；其他 HR 的岗位、投递 | 403 | 4 |
| 其他用户的会话 | 403 | 1 |
| 超过 1000 字符的消息 | 400 | 1 |
| 同会话改变招聘上下文 | 409 | 1 |

每个被拒绝请求前后都检查适配器调用计数不变。合法请求只允许固定合成问题和标记上下文，记录器最多委托生产客户端 3 次；真实状态及结果断言在证据落盘后执行，失败不会触发自动重试。

以下结论由实际断言支撑：

- 使用生产 `JwtService` 签发测试 JWT，真实安全过滤链校验 JWT 并经合成角色 Mapper 重新加载角色；没有调用登录注册 HTTP。
- 学生首轮、HR 请求分别带入生产服务端角色提示。续聊的五条实际消息为系统提示、授权上下文、上一轮问题、上一轮完整真实回答、当前问题，逐项核对了上一轮问答。
- 对已有匹配记录的查询同时限定 `job_id=9` 和 `resume_id=5`，检查表达式及绑定值；只初始化内存实体元数据，不执行 SQL。
- 三条成功 HTTP 响应均返回只读 75.00、来源 `ai-match-result`、`humanReviewRequired=true`。75.00 是测试中已有的合成匹配记录，**本次没有重新运行规则计算**，不能用它宣称规则分计算验收或模型增益。
- 岗位、简历、投递和匹配实体前后完整快照相等，SUBMITTED 状态不变。六个 Mapper 的全部实际调用只允许 `selectById`、`selectCodesByUserId`、`selectOne`；出现任何写调用均会使测试失败。这证明本次服务路径无数据写调用，不是数据库持久化检查。
