# 前端界面视觉与交互优化验收记录（2026-10-11）

用户追加的独立小模块：只优化现有前端界面的视觉与交互呈现，不新增业务功能、接口、路由或数据库变更。分支 `King/ui-visual-polish-20261010`，基线 `King/review-regression-20261010`（`98ef61f`）。开始时工作区已有 14 个前端文件改动和 2 个新组件（上一轮未完成的美化半成品），本次在其基础上完成、修正并验证，没有丢弃。

## 主要问题与设计方向

| 问题 | 处理 |
| --- | --- |
| `theme.css` 与 `styles.css` 颜色、组件规则重复并互相覆盖 | `theme.css` 只放设计变量和 Element Plus 皮肤；`styles.css` 只做布局与共享模式，颜色全部引用变量（规则/模型/人工三类标记、正向/缺口/风险色也已变量化） |
| 标题区、介绍区过高，岗位与表单被推到首屏以下 | 标题压缩为 24px 单行说明，统计条改为紧凑卡片；登录页品牌区自适应、表单列固定 360–440px 并垂直居中，手机端表单排在介绍之前 |
| HR 9 个功能标签拥挤、窄屏溢出 | 新增 `WorkspaceNav`：桌面按“岗位与投递 / 辅助建议 / 助手”分组；≤640px 改为单行横向滚动条并自动露出当前标签，标签文字完整；保留 `role="tablist"` 和方向键切换 |
| 匹配分、模型建议、人工决定区分不清 | `MatchResultCard` 统一展示“规则匹配分 · 只读”、技能覆盖率进度条、匹配技能、技能缺口、计算说明和评分来源；模型内容用紫色“模型辅助建议”，降级用琥珀色“降级说明”，人工决定用醒目提示与确认框 |
| HR 投递表格窄屏挤压，状态下拉显示原始枚举 `SUBMITTED` | 表格交给 `el-table` 自身横向滚动并固定“处理（需确认）”列；下拉改为“变更为…”占位，当前状态选项禁用；首列同时显示“当前：已投递” |
| 文件导入按钮随浏览器语言显示英文 | 原生 `input` 保持可聚焦，外观改为中文“选择 PDF / TXT 文件”按钮并显示所选文件名 |
| 注册角色单选使用即将废弃的 `label` 作为值 | 改为 `value`，提交值仍为 `STUDENT` / `HR` |

## 保留的业务行为

路由、角色导航、路由守卫、API 调用与数据绑定未改。简历导入仍为“提取 → 可编辑预览 → 确认 → 新建草稿”；助手切换上下文/新对话清空消息、草稿和 `conversationId`，请求期间禁用输入，回复按纯文本渲染；匹配分只读且注明“不代表熟练度或录用概率”；HR 状态更新仍需确认，取消不发请求；外部岗位仍跳转原站申请。

## 验证

区分三类：

1. **前端构建（实际执行，通过）**：在本机项目目录执行 `node node_modules\vite\bin\vite.js build`（等价于 `pnpm --dir frontend build`），共 3 次，最后一次 `EXIT=0`，2267 个模块。仅保留既有 VueUse `#__PURE__` 注释提示和 >500 kB chunk 提示。
2. **界面 + 模拟接口验证（实际执行，77/77 通过）**：将最终构建产物用独立静态服务托管，Playwright + Chromium 拦截全部 `/api/*` 请求返回合成数据（标题均带“[合成]”）。检查 1440 / 1024 / 768 / 390 宽度和以下行为：
   - 登录、注册空表单只显示校验、不发请求；未登录访问 `/app` 被重定向；三种角色登录后进入各自工作台。
   - 四个宽度下登录、学生、HR、管理员、外部岗位页面均无页面级横向滚动；HR 导航无截断标签，手机端切换到“JD 分析”后当前标签在可视范围内。
   - 岗位关键词筛选发送 `keyword`，结果从 2 条变 1 条；切换岗位后详情更新、`aria-pressed` 正确；空薪资显示“薪资面议”；手机端选择岗位后详情滚入视野。
   - 简历导入：预览可编辑且未保存；提取警告可见；取消导入不发请求；确认后 POST 新草稿且包含用户修改文本，未调用任何更新已有简历的接口。
   - 匹配卡片显示技能覆盖率、匹配技能、技能缺口、来源 `local-skill-coverage-v1` 及“不代表录用概率”，无可编辑控件。
   - 助手：等待期间输入禁用并显示等待状态；`<script>` / `<img onerror>` 按文本显示且未执行；模型回复与降级回复分别标注；续聊复用 `conversationId`；切换上下文清空消息和草稿，下一次请求不带 `conversationId`；输入上限 1000 字；“新对话”清空。
   - HR 状态：确认框说明人工决定；取消后 PATCH 次数为 0；确认后恰好 1 次 PATCH，值为 `REVIEWING`；当前状态选项禁用；390px 下表格在自身区域滚动且“处理”列可见。
   - 外部岗位：暂存数据提示可见；分页请求 `page=2`；申请链接指向 jobicy.com，`target=_blank` 且带 `noopener`。
   - 管理员：统计数字来自接口数据，3 个图表渲染为 canvas。
   - 键盘方向键可在工作台标签间移动焦点；运行期间无页面错误或 Vue/Element Plus 警告。
3. **真实后端联调（本次未执行）**：没有启动 Spring Boot、MySQL、Redis，也没有调用 DeepSeek 或 Jobicy。上述结果只证明界面状态与请求参数，不证明真实接口、权限或数据正确。
