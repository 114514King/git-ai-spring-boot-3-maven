## 问题及修复

| 问题 | 触发与影响 | 修复结果与证据 |
| --- | --- | --- |
| P1：助手旧会话混入其他候选人/对象 | 同一用户携带旧 `conversationId` 切换投递，或从投递进入通用上下文，服务端仍带入旧历史；可能将候选人一的内容混入候选人二的说明 | 会话绑定服务端解析后的投递、岗位和简历 ID；不同对象返回统一 409，且不再次调用模型。修复前新增两项服务测试失败，修复后服务和 MockMvc 契约测试通过；页面 409 后保留草稿、停用发送，支持新对话 |
| P2：登录角色/登录态不完整 | 原登录页面和访客页守卫固定跳往学生工作台；认证 store 仅判断令牌是否存在，忽略有效期 | 登录响应返回服务端查询的 `roles`，本次查询层用模拟 mapper 验证；按角色进入 ADMIN/HR/STUDENT 工作台，限制跨角色页面导航；路由跳转时核对有效期，清除损坏或过期记录。三个角色登录、HR 误入学生页、过期令牌及损坏角色 JSON 均通过浏览器检查；登录 JSON 字段经实际 Spring 控制器 MockMvc 验证 |
| P2：薪资空值变成 0，并产生类型警告 | 输入框初始化/编辑时使用空字符串；清空数字框后组件返回 null，原提交代码 `Number(null)` 变成 0 | 输入框使用 null 表示空薪资，提交保留 null；浏览器验证“输入 1000 → 清空 → 保存”请求体中上下限为 null，且没有 String/Number 属性警告 |
| P2：空表单出现未处理异常 | 点击创建岗位等按钮，`validate()` 拒绝后异常逸出事件处理器；浏览器记录未处理错误 `Object` | 登录、注册、岗位、简历四处表单校验失败正常结束，展示字段错误并且不发送写请求。HR 修复前复现，修复后四个空表单均通过检查 |
| P2：长历史导致后续对话超限 | 每条合成模型回复 20,000 字符，继续对话后输入达到 40,313 字符，超过适配器 24,000 上限；消息条数限制不能限制总字符 | 使用适配器共享上限，裁减最旧完整问答轮次并返回明确 warning，保留当前问题与授权上下文；修复前预算测试失败，修复后通过。奇数历史限额不会发送孤立助手回复，单轮问答原子追加 |

上下文修复解决的是同一用户内不同招聘对象的历史混用。其他用户、不同角色、非本人简历或非本人岗位的访问仍由服务端权限校验拒绝；不把此问题说成已实测跨用户泄露。
