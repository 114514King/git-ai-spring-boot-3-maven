# 外部招聘数据接入方案

核查日期：2026-10-01。本文是后续模块设计，不代表已经接入第三方数据。

用户优先选择 BOSS直聘、智联招聘和前程无忧。当前系统仅展示本平台 HR 发布的岗位，投递流转也仅在本平台内完成。

## 国内平台核查结果

| 来源 | 本次能够确认的内容 | 接入前需要补齐 |
| --- | --- | --- |
| BOSS直聘 | 找到 BossHi 的官方开放文档，但其示例是企业消息和通讯录，不能当作 BOSS直聘岗位查询 API | 招聘数据合作渠道、岗位读取接口文档、应用凭证和可展示范围 |
| 智联招聘 | 找到企业帮助中心；本次未找到可直接用于全站岗位同步的公开接口文档 | 向官方确认是否提供岗位数据合作接口，以及账户与授权条件 |
| 前程无忧 | 找到企业招聘服务入口；本次未找到可直接用于全站岗位同步的公开接口文档 | 确认企业/合作接口、数据导出权限及展示和更新范围 |

“本次未找到”不是证明平台不存在合作接口。企业账户、职位发布接口和全站岗位读取权限也不能相互替代。未对三家平台进行真实 API 联调。

官方参考：[BossHi API 调用说明](https://histatic.zhipin.com/front/bosshi-mp-docs/service/ready/apiCall/callProcess/callApi.html)、[智联企业帮助中心](https://rd6.zhaopin.com/app/help)、[前程无忧企业招聘服务](https://mall.51job.com/)。

## 建议实施顺序

1. 来源与链接模块：记录来源平台、原始岗位 ID/URL、企业名称、城市、岗位要求和更新日期，明确展示“本平台岗位”或“外部岗位”。
2. 授权文件导入模块：导入用户或企业有权使用的 CSV/JSON 数据，先预览和校验，再确认保存。接口凭证到位之前，这条路径更容易验证。
3. 单一平台适配模块：拿到实际文档和授权后，在 Spring Boot 服务端实现读取、字段映射、限频、超时和失败记录，再逐一扩展其他平台。
4. 更新与下架模块：按来源与原始岗位 ID 去重，记录最近成功同步；失败时保留旧数据并标识状态，不能因单次网络失败将全部岗位下架。

外部岗位先提供“前往原站申请”。点击不能生成本平台的“已投递”记录，因为无法据此确认外站投递是否完成。本平台 HR 管理、候选人排序和投递状态继续只处理本平台记录。

## 与现有系统的接口边界

- 外部岗位应使用独立来源记录和只读查询接口。现有 `job_posting` 依赖本平台 HR 归属，不能把导入岗位任意挂到某个 HR，或者直接混入现有投递接口。
- 必要字段建议：`source`、`externalId`、`sourceUrl`、`applyUrl`、`title`、`companyName`、`locationText`、`employmentType`、`salaryText`、`requirements`、`description`、`sourceUpdatedAt`、`lastSyncedAt`、`status`。
- 薪资应保留币种、周期、月数及原文；不能把“万/年”“千/月”“13薪”直接按本平台数值薪资展示。用工类型不能确定时保留未知。
- 外部岗位 HTML 转成清理后的纯文本；来源链接校验 HTTPS 和来源域名，不直接执行第三方脚本或渲染未处理的 HTML。
- 同步服务只访问配置好的平台域名和接口，凭证保存在服务端配置中。外部岗位不需要收集联系人、聊天、用户简历等个人数据。
- 外部 JD 若不能可靠分离“岗位要求”，不直接沿用技能覆盖率分数；先核对字段，避免把整个岗位介绍误当作要求。

以上字段和边界仅为设计，未新增数据库表、接口、同步任务或前端占位按钮。按每日计划另立任务实现。

## 可以核实的其他公开接口

[Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html) 明确允许无认证 GET 读取指定企业招聘板的岗位。[Lever Postings API](https://github.com/lever/postings-api) 提供指定企业公开岗位读取。这些可以作为适配器学习参考，覆盖范围是指定企业，不是国内三大平台，也不意味着任意内容都可以重新分发。
