# 受控比较人工质量复核

本模板用于审查 `GET /api/admin/evaluations/day30-controlled-comparison` 返回的固定合成场景。接口的关键词检查只是提示；报告始终返回 `qualityReviewStatus=PENDING_HUMAN_REVIEW`，每个场景的 `manualReviewStatus` 也保持该值。生成文本、模型自称已通过或没有风险关键词均不能完成复核。本模块没有复核写入接口或持久化，人工记录不会改变 API 状态，也不会改变匹配分或投递状态。

## 获取和保留执行证据

1. 使用管理员 JWT 在本机请求评估接口。保持 `DEEPSEEK_ENABLED=false` 可检查降级；显式启用时会发送 3 次固定合成请求。不要把真实 CV、密钥或 JWT 放入记录。
2. 在个人、不入库的文件中保留完整 JSON、北京时间执行时间、实际后端 commit、开关/模型配置（不含密钥）。不要仅靠固定的 `evaluationId` 区分执行。
3. 复制 `scenarioSetVersion`、`scenarioSetHash` 和每个场景的 `inputHash`、`ruleEvidenceHash`、`modelPromptHash`。比较两次执行前先核对这些字段；耗时和生成文本可以变化。
4. 独立标记来源为默认降级、模拟响应或真实 DeepSeek。`modelGenerated=true`、`runMode` 和模型名本身不能证明真实调用；真实调用还需实际执行及 HTTP/适配器证据。

本机获取示例，JWT 仅在当前进程环境中配置；结果留在变量中，按个人证据存储要求保留：

```powershell
$evaluationHeaders = @{ Authorization = "Bearer $env:ADMIN_JWT" }
$evaluationReport = Invoke-RestMethod -Method Get `
    -Uri 'http://127.0.0.1:8080/api/admin/evaluations/day30-controlled-comparison' `
    -Headers $evaluationHeaders
$evaluationReport.data
```

## 每个场景的审查方法

- 复核 `jobRequirements` / `resumeText` 中的已识别技能，按匹配数量除以所需数量核对规则分，并核对匹配项和完整缺口。规则覆盖率不证明技能熟练度或录用概率。
- 分别阅读 `ruleOnlySummary` 和 `rulePlusModelSummary`，记录模型实际增加的追问、核验证据或风险说明。每项评价都引用具体原文或指出遗漏，不把流畅措辞当作额外贡献。
- 有缺口时逐项检查是否覆盖、是否把缺口误称已满足；无缺口时检查熟练度、真实性和岗位语境，不捏造额外缺口。
- 检查无依据经历、改分、自动录用/拒绝和误导性“人工已通过”表述。关键词命中存在漏报/误报，应按上下文判断并记录证据。
- 模型未生成时把贡献标为“不适用：未生成”，只能复核规则和降级。部分生成时逐场景标记，不把降级场景算成有效模型样本。

## 空白记录模板

以下只定义填写位置，不代表已经执行或通过。复制后由实际复核人填写；缺少执行/输出证据时保持“待执行/待复核”。模型自述不得填入复核人或审批字段。

| 执行字段 | 待填写内容 |
| --- | --- |
| 北京时间、后端完整 commit、结果文件 | 待实际执行后填写 |
| 来源、模型状态、模型配置及实际调用证据 | 默认降级 / 模拟响应 / 真实调用；证据另附 |
| 场景版本与集合哈希 | 从当次 JSON 复制 |
| 复核人、复核时间 | 待实际人工审查后填写 |

每个场景各填写一份下表，引用同一次执行的输出：

| 审查字段 | 待填写内容 |
| --- | --- |
| 场景 ID、角色、三种哈希 | 从当次 JSON 复制 |
| 规则证据核对 | 分数、所需/匹配/缺失技能及核对依据 |
| 模型状态、耗时、token、输出证据 | 从当次 JSON 复制；降级写明状态 |
| 缺口覆盖或无缺口证据核验 | 按每个缺口填写覆盖/遗漏/误述，或标记不适用 |
| 无依据经历或越界表述 | 引用原文、上下文及风险判断，未审查留待复核 |
| 相对规则基线的额外贡献 | 有 / 无 / 不确定 / 不适用，附具体内容和理由 |
| 人工质量结论与局限 | 待复核；结论只针对当前合成场景 |

固定 3 场景是小样本验证，人工结论不能外推为真实招聘准确率或效率提升；合成模型契约检查、真实模型调用、真实 MySQL 端到端和真实协作经历应分别记录。本文件不宣称其中任何真实验收已完成。
