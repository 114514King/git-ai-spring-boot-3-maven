## 设计与实现

内置 Image Gen 生成 [学生工作台参考稿](student-concept.png)。提示要求保持 Vue 3 / Element Plus 的真实文本与控件、青绿色主色、白色面板、浅灰页面、现有选项卡、岗位列表与详情双栏。图片仅作参考，不用图片替代页面控件。

实现使用 `theme.css` 提供共享设计变量与组件样式，`PlatformBrand.vue` 统一页头，`AuthIntro.vue` 复用账号页介绍。登录注册业务、角色接口、路由守卫与后端保持现有流程。

## 与参考稿的比对

通过内置浏览器截图，并用 `view_image` 同时检查参考稿与最终学生桌面截图。检查范围如下：

| 项目 | 检查与处理 |
| --- | --- |
| 配色 | 页面 `#f4f7f8`、面板 `#ffffff`、主色 `#0f766e`；已统一 Element Plus 按钮与选中标签 |
| 布局 | 开放式标题区、统计条、水平选项卡、左列表右详情；手机变为单列 |
| 字体 | 桌面主标题 34px，手机 29px；面板标题 21px，操作项 14–15px，岗位标题 16px |
| 岗位列表 | 薪资独立突出；用工类型中文化；选中项浅绿色底与左边线；添加键盘焦点和 aria-pressed |
| 详情信息 | 将用工类型与发布时间改为紧凑元信息，保留描述、要求、简历选择和原有操作 |
| 页头与图标 | 页头公文包使用线条图形，现有功能图标沿用 Element Plus；不增加无操作含义的下拉箭头 |
| 表单与标签 | 筛选字段添加可见标签；修正岗位状态标签在卡片布局中被压缩的问题 |

首屏文案已对照参考稿和现有业务：主标题、引导语、六个学生选项卡、公开岗位说明、筛选与投递操作一致。以下是为兼容现有业务保留的差异：

- 保留现有第五项“行动计划”统计，计数来自实际页面状态。
- “公开岗位”计数表示当前筛选结果，不称“可投递岗位”，因为能否投递还取决于发布简历等条件。
- 保留原有“AI 匹配”统计名称；提示说明技能覆盖与差距。
- 页头操作只保留刷新与退出，没有加入参考图中未经现有角色流程支持的跨角色按钮。
- 保留真实薪资数值与发布时间，不转换成参考稿的示例薪资/公司信息；截图中的公司均注明“演示”。
- 登录/注册以及 HR/管理员沿用相同设计系统，保留各自现有功能，不按学生参考图改变信息结构。

已按参考稿核对视觉系统与核心布局；上述业务兼容差异为有意保留，非逐像素复刻。

## 验证方法与结果

- `pnpm --dir frontend build` 通过。保留项目已有的第三方注释处理和大 chunk 提示。
- 内置浏览器验证 1280×720 的默认桌面、1505×1045 的参考稿尺寸视口与 390×844 手机视口。参考稿原始 PNG 为 1505×1045；桌面全页截图包含滚动内容，宽度扣除滚动条后为 1490px。
- 登录成功后进入学生端；输入“前端”并筛选后，岗位从 3 个减少到 1 个；选择岗位后详情更新。
- 用已发布的演示简历投递后，投递统计增加并进入投递记录；确认“已投递”状态可见。
- 切换“我的简历”，确认既有文件导入入口、简历编辑和列表仍可见。
- HR 岗位编辑/列表及管理员五项统计和四个图表容器可加载。
- 手机端学生、HR、管理员、注册页面未出现页面横向溢出；学生页面双栏折叠，统计条改为两列，选项卡可横向滚动。
- 注册与登录导航以真实 RouterLink 验证；键盘 Enter 可从注册返回登录。

验证使用仅绑定 `127.0.0.1` 的隔离模拟 API 和合成岗位/简历，不连接真实 MySQL，不调用外部平台，不证明真实数据库端到端或角色授权已经重新测试。没有修改后端，未重复运行后端测试。HR 原有薪资数字输入框的空字符串类型警告仍存在；本次不改动其业务字段处理。

临时预览服务、模拟 API 文件均在交付前移除，演示数据不进入产品代码。
